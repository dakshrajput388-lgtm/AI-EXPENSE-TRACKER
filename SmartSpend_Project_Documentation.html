1.0 Executive Summary & System Architecture

1.1 Project Overview & Motivation

SmartSpend is an enterprise-grade desktop personal finance management application engineered in pure Java 21 and JavaFX. While typical student projects offer primitive command-line interfaces or superficial web forms, SmartSpend delivers an end-to-end desktop experience combining industrial software engineering patterns with modern artificial intelligence.

The application allows users to register secure accounts, track daily multi-category expenses and income streams, establish monthly category budgets with real-time overspending alerts, visualize financial health through interactive charts, export structured reports to disk, and converse with an integrated AI Financial Assistant powered by the Google Gemini API.

3.0 Object-Oriented Programming (OOP) Deep Dive

3.1 The Abstract Base Class: Transaction.java

In financial systems, every entry is either an expenditure or an earning. A generic "transaction" cannot exist by itself. Therefore, we declare Transaction as an abstract class: 

// Package: com.smartspend.model
public abstract class Transaction {
    protected int id;
    protected int userId;
    protected double amount;
    protected String category;
    protected String description;
    protected LocalDate date;

    // Default Constructor
    public Transaction() {}

    // Overloaded Constructor with Constructor Chaining
    public Transaction(int userId, double amount, String category, String description, LocalDate date) {
        this(0, userId, amount, category, description, date);
    }

    public Transaction(int id, int userId, double amount, String category, String description, LocalDate date) {
        this.id = id;
        this.userId = userId;
        this.amount = amount;
        this.category = category;
        this.description = description;
        this.date = date;
    }

    // Abstract method: MUST be implemented by child classes
    public abstract String getTransactionType();

    // Virtual method providing common baseline summary
    public String getFormattedSummary() {
        return String.format("[%s] %s: $%.2f on %s", getTransactionType(), category, amount, date);
    }

    // Encapsulated getters and setters...
}

3.2 Inheritance and Dynamic Polymorphism: Expense.java & Income.java

Expense and Income extend Transaction, reusing its fields and overriding behavior: 

// Package: com.smartspend.model
public class Expense extends Transaction {
    public static final List<String> CATEGORIES = Arrays.asList(
        "Food", "Shopping", "Travel", "Education", "Transport", "Entertainment", "Healthcare", "Other"
    );

    public Expense(int userId, double amount, String category, String description, LocalDate date) {
        super(userId, amount, category, description, date); // Constructor Chaining
    }

    @Override
    public String getTransactionType() {
        return "EXPENSE"; // Dynamic Polymorphism
    }

    @Override
    public String getFormattedSummary() {
        return String.format("[-] %s: $%.2f (%s)", category, amount, description);
    }
}
Key Point for Sir: If we have a polymorphic collection List<Transaction> list containing both Expense and Income objects, iterating over the list and calling t.getTransactionType() triggers dynamic method dispatch, invoking the correct subclass implementation at runtime without explicit type casting.

4.0 Database & JDBC Persistence Layer

4.1 The Singleton Connection Manager

Managing multiple database connections in desktop software leads to port exhaustion and resource contention. SmartSpend uses the Singleton Pattern to centralize connection lifecycle and support seamless offline fallback: 

// Package: com.smartspend.database
public class DatabaseConnection {
    private static DatabaseConnection instance;
    private Connection connection;

    // Private constructor prevents external instantiation
    private DatabaseConnection() {
        connect();
    }

    // Thread-safe synchronized access
    public static synchronized DatabaseConnection getInstance() {
        if (instance == null) {
            instance = new DatabaseConnection();
        }
        return instance;
    }

    private void connect() {
        try {
            // Attempt primary MySQL connection
            Class.forName("com.mysql.cj.jdbc.Driver");
            this.connection = DriverManager.getConnection(
                "jdbc:mysql://localhost:3306/smartspend_db?createDatabaseIfNotExist=true",
                "root", "password"
            );
            System.out.println("[DB] Connected to MySQL successfully.");
        } catch (Exception e) {
            System.err.println("[DB] MySQL unavailable. Falling back to embedded H2 database...");
            try {
                // Seamless in-memory fallback
                Class.forName("org.h2.Driver");
                this.connection = DriverManager.getConnection("jdbc:h2:mem:smartspend;DB_CLOSE_DELAY=-1");
                System.out.println("[DB] In-Memory H2 Database initialized successfully.");
            } catch (Exception h2Ex) {
                throw new DatabaseException("Fatal: Failed to initialize database.", h2Ex);
            }
        }
    }
}

4.2 Protection Against SQL Injection Attacks

Traditional string concatenation in SQL queries ("SELECT * FROM users WHERE name = '" + input + "'") is vulnerable to SQL injection. SmartSpend strictly uses PreparedStatement: 

// Package: com.smartspend.dao (ExpenseDao.java)
String sql = "INSERT INTO expenses (user_id, amount, category, description, expense_date) VALUES (?, ?, ?, ?, ?)";
try (Connection conn = DatabaseConnection.getInstance().getConnection();
     PreparedStatement ps = conn.prepareStatement(sql, Statement.RETURN_GENERATED_KEYS)) {
    
    ps.setInt(1, expense.getUserId());
    ps.setDouble(2, expense.getAmount());
    ps.setString(3, expense.getCategory());
    ps.setString(4, expense.getDescription());
    ps.setDate(5, java.sql.Date.valueOf(expense.getDate()));
    
    return ps.executeUpdate() > 0;
} catch (SQLException e) {
    throw new DatabaseException("Error persisting expense record", e);
}
Why this is safe: The database engine compiles the SQL query template first with ? placeholders. User inputs are subsequently bound purely as literal parameters, preventing attackers from injecting malicious SQL commands like ' OR 1=1; DROP TABLE users; --.

5.0 Exception Handling Architecture

5.1 Custom Exception Class with Exception Chaining

Rather than leaking low-level, database-specific SQLException instances into UI controllers, SmartSpend wraps persistence failures into a domain-specific DatabaseException: 

// Package: com.smartspend.util
public class DatabaseException extends RuntimeException {

    public DatabaseException() {
        super("A database error occurred in SmartSpend.");
    }

    public DatabaseException(String message) {
        super(message);
    }

    // Constructor Chaining preserving root cause for debugging
    public DatabaseException(String message, Throwable cause) {
        super(message, cause);
    }
}

5.2 Multi-Tier Exception Propagation Strategy

Application Tier Handled Exceptions Design Decision & Action
DAO Layer SQLException Catches driver exceptions, translates them to DatabaseException(msg, e), ensuring database isolation.
Service Layer NumberFormatException, DateTimeParseException Validates business parameters; throws user-friendly validation exceptions before persistence calls.
Network Tier HttpTimeoutException, IOException Catches Gemini network dropouts; seamlessly activates the offline rule-based financial analyzer.
Controller / UI DatabaseException, Exception Catches top-level exceptions and displays non-blocking JavaFX AlertHelper.showError() dialogs.

5.3 Automatic Resource Management (Try-with-Resources)

Every class interacting with external streams or database cursors implements Java's AutoCloseable interface. SmartSpend uses try-with-resources blocks: 

try (Connection conn = DatabaseConnection.getInstance().getConnection();
     PreparedStatement ps = conn.prepareStatement(query);
     ResultSet rs = ps.executeQuery()) {
    while (rs.next()) {
        // Process records
    }
} // Resources automatically closed in reverse order of declaration even if an exception occurs

7.0 Modern Java: Streams, Lambdas & File I/O

7.1 Functional Programming with Java 8 Streams

Instead of imperative for-loops with mutable counters, ReportService.java utilizes declarative stream pipelines: 

// Package: com.smartspend.service (ReportService.java)

// 1. Filtering by dynamic date range
List<Expense> filteredExpenses = allExpenses.stream()
    .filter(e -> !e.getDate().isBefore(startDate) && !e.getDate().isAfter(endDate))
    .collect(Collectors.toList());

// 2. Computing aggregate financial total
double totalExpense = filteredExpenses.stream()
    .mapToDouble(Expense::getAmount)
    .sum();

// 3. Category grouping and accumulation
Map<String, Double> categoryBreakdown = filteredExpenses.stream()
    .collect(Collectors.groupingBy(
        Expense::getCategory,
        Collectors.summingDouble(Expense::getAmount)
    ));

7.2 Disk Export via Java File I/O

FileExportUtil.java produces RFC-4180 standard CSV files for reporting: 

// Package: com.smartspend.util (FileExportUtil.java)
public static boolean exportExpensesToCSV(List<Expense> expenses, File targetFile) {
    try (BufferedWriter writer = new BufferedWriter(new FileWriter(targetFile))) {
        // Write CSV Header
        writer.write("ID,Date,Category,Amount,Description");
        writer.newLine();

        for (Expense e : expenses) {
            String line = String.format("%d,%s,%s,%.2f,%s",
                e.getId(),
                e.getDate(),
                escapeCsv(e.getCategory()),
                e.getAmount(),
                escapeCsv(e.getDescription())
            );
            writer.write(line);
            writer.newLine();
        }
        return true;
    } catch (IOException e) {
        System.err.println("[Export] File write error: " + e.getMessage());
        return false;
    }
}

8.0 Multithreading & Asynchronous AI Integration

8.1 The JavaFX UI Single-Thread Rule

JavaFX employs a single-thread model where all scene graph modifications and user input events are handled strictly by the JavaFX Application Thread. If an HTTP request to the Google Gemini API (taking 1-3 seconds) is executed directly on this thread, the UI freezes, buttons stop reacting, and the operating system marks the application as "Not Responding".

8.2 Non-Blocking Execution with JavaFX Task & Platform.runLater()

To maintain a responsive UI, SmartSpend offloads API calls to background worker threads: 

// Package: com.smartspend.controller (AIAssistantController.java)
public void sendMessageToAI(String prompt) {
    // Show user message and temporary typing indicator on UI
    chatContainer.getChildren().add(new UserChatBubble(prompt));
    TypingIndicator indicator = new TypingIndicator();
    chatContainer.getChildren().add(indicator);

    // Run network I/O on a background thread
    Task<String> aiTask = new Task<>() {
        @Override
        protected String call() throws Exception {
            return geminiService.generateFinancialAdvice(userId, prompt);
        }
    };

    aiTask.setOnSucceeded(e -> {
        String response = aiTask.getValue();
        // Safely update UI components on the JavaFX Application Thread
        Platform.runLater(() -> {
            chatContainer.getChildren().remove(indicator);
            chatContainer.getChildren().add(new AIChatBubble(response));
        });
    });

    aiTask.setOnFailed(e -> {
        Platform.runLater(() -> {
            chatContainer.getChildren().remove(indicator);
            chatContainer.getChildren().add(new AIChatBubble("AI Service temporarily offline."));
        });
    });

    new Thread(aiTask).start();
}

10.0 Top 20 Faculty Viva Questions & Model Answers

1. Why did you use an Abstract Class for Transaction instead of an Interface?

Because Expense and Income share common fields (id, amount, category, date) and constructor logic. Interfaces before Java 8 could not hold state or fields, and even now cannot hold constructors. An abstract class is the proper object-oriented choice when sharing state and partial implementation across closely related subclasses.

2. How does your application prevent SQL Injection?

We strictly use PreparedStatement with ? placeholders for all dynamic inputs. The SQL query structure is pre-compiled by the database engine prior to binding values, ensuring any special characters are treated purely as literal strings rather than executable SQL.

3. What is the benefit of the Singleton pattern in DatabaseConnection?

It guarantees that only a single instance of the database connection manager exists throughout the JVM lifecycle. This centralizes connection configuration, prevents port exhaustion, and coordinates our seamless fallback to the in-memory H2 database.

4. What is the difference between Checked and Unchecked Exceptions in your project?

SQLException is a checked exception that requires explicit handling. We translate it into our custom DatabaseException, which extends RuntimeException (unchecked). This prevents boilerplate throws declarations across our service and controller layers while allowing controllers to catch it where appropriate.

5. Why is try-with-resources better than try-catch-finally?

Try-with-resources automatically closes all declared resources implementing AutoCloseable in reverse order upon exiting the block, even if an exception occurs. This eliminates verbose, error-prone nested finally blocks where closing one resource could throw an exception and skip closing others.

6. What happens if the local MySQL server is not installed or turned off?

Our DatabaseConnection class catches the connection failure, logs a notification, and automatically initializes an embedded in-memory H2 database. Tables and default records are seeded automatically, ensuring the app runs reliably during evaluation.

7. Why is multithreading required for the Gemini AI assistant in JavaFX?

JavaFX operates on a single Application Thread. An HTTP request takes 1-3 seconds; executing it on the UI thread would block the event loop, causing the window to freeze and appear "Not Responding". Running it in a background Task keeps the UI smooth.

8. What does Platform.runLater() do?

JavaFX UI elements are not thread-safe and can only be updated from the JavaFX Application Thread. Platform.runLater(Runnable) submits a task onto the UI thread's event queue to be executed safely when background network threads finish.

9. How do Java 8 Streams benefit your financial report calculations?

Streams provide declarative, functional processing: expenses.stream().filter(...).mapToDouble(...).sum() replaces multiple temporary variables and nested for loops, significantly improving readability and reducing indexing bugs.

10. How are passwords stored securely in the database?

In AuthService.java, passwords are hashed using SHA-256 via Java's MessageDigest. We combine the password with a per-user salt before hashing, ensuring that raw passwords are never stored in plaintext.

11. What is the role of PropertyValueFactory in TableView?

It uses Java Reflection to automatically inspect the getter methods of the model class (e.g., getCategory() in Expense) and bind that value directly to the corresponding TableColumn cell.

12. Why did you use Java Generics in CrudDao<T>?

Generics allow us to write a single, reusable interface contract for all persistence operations (save, findById, delete) while enforcing compile-time type safety for Expense, Income, Budget, and User.

13. What is the difference between Method Overloading and Method Overriding in your code?

Method Overriding occurs in Expense and Income where both override getTransactionType() from Transaction. Method Overloading occurs in Transaction constructors having different parameter signatures.

14. Why is java.time.LocalDate preferred over java.util.Date?

java.time.LocalDate is immutable and thread-safe. It separates date from time and timezone concerns and avoids the deprecated 0-indexed month bugs inherent in legacy java.util.Date.

15. How does the application ground AI answers in real user financial data?

Before sending the HTTP request, GeminiService queries the database for monthly totals, top categories, and savings rates, injecting these real metrics into the prompt context for personalized guidance.

16. What is the DAO (Data Access Object) design pattern?

The DAO pattern isolates business logic from the underlying persistence implementation. Services interact with ExpenseDao interfaces without needing to know whether records reside in MySQL, H2, or files.

17. How does the system handle foreign keys when a user is deleted?

Our database schema specifies ON DELETE CASCADE for all child tables (expenses, incomes, budgets), guaranteeing that deleting a user automatically cleans up associated records without orphan rows.

18. What is RFC-4180 compliance in your CSV exporter?

It is the formal specification for comma-separated values. If a description contains commas, quotes, or newlines, our FileExportUtil wraps the field in double quotes and escapes internal quotes with double-quotes.

19. How does SessionManager maintain logged-in user state?

It is implemented as a Singleton holding a reference to the active User object. Any view or controller can call SessionManager.getInstance().getCurrentUser() to retrieve the user's ID and permissions.

20. What makes your project stand out compared to standard expense trackers?

SmartSpend combines pure Java 21 desktop engineering, multi-engine database persistence with automatic fallback, complete 4-pillar OOP design, multithreaded AI integration, and production-quality visual charting.
